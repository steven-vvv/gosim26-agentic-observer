# 公开场景策略迁移研究报告（2026-09-28）

## 结论

本轮没有找到足以替换 `v3/agents/observer` 默认策略的新参数或新算法。当前推荐版本保持不变，原因是已有有效机制已经在默认策略中，新增方向在配对实验中没有稳定收益，或只在小样本上出现噪声内的正变化。

这不等于证明当前策略全局最优，也不能证明排行榜高分队伍只做了特定调参。可以确认的是：它们对当前公开项目场景构成了实际的公开场景威胁；现有证据还不足以把这种优势外推为隐藏未知场景中的稳定优势。下一步最有价值的工作是拿到可比较的多场景线上结果，并核验真实平台模型调用，而不是继续在单个公开场景上追逐最高分。

## 研究问题与判定规则

本轮计划记录在 [`2026-09-28-public-transfer-research.md`](2026-09-28-public-transfer-research.md)，分成四个假设：

1. 排行榜高分来自公开场景专门调参、预计算或提交轨迹复用。
2. 排行榜高分来自可迁移的通用策略改进。
3. 评分或场景信息存在我们尚未复现的差异。
4. 我们的策略仍有一个可以从合法当前快照中得到、但尚未实现的方向。

每个候选以相同代码快照和相同场景配对比较。采用门槛为：均值不回退、标准误不能掩盖收益、完成度和 REQUIRED 不恶化、墙钟预算不恶化。单场最高分不能覆盖配对均值回退。

| 候选 | 相对默认均值 | 分项观察 | 判定 |
|---|---:|---|---|

## 已确认有效并已整合的策略

这些不是本轮新改动，而是当前默认 agent 已经包含、且有配对实验支持的部分：

- **机会价格规划**：按 `(当前边际收益 - 未来机会价值) / 曝光秒数` 排序，处理时间稀缺下的让位。
- **规划内覆盖边际**：将 Jain 均匀度的边际加入规划，防止时机优化把某一区域耗尽。
- **夜内重规划与预算降级**：正常按小时重规划；墙钟压力升高时降为每夜一次，再关闭规划，保证协议完成。
- **分段几何精算与有限 rollout**：对粗排候选按时隙边界重算质量和档位，并对少量候选做短期前向推演。
- **REQUIRED、请求和短窗口保护**：保留强约束，不能为了瞬时科学分牺牲完成度。
- **异常与寒潮处理**：精确读数、故障单次确认、NOVA/红化标签、寒潮在线效率修正和全局下沉过滤。
- **协议与运行回退**：模型建议只在确定性候选集内生效；非法响应、超时或连续失败回退确定性结果，模型关闭时主路径仍可独立运行。

这些机制共同解释了为什么当前策略已经明显高于早期收益贪心。排行榜差距不能通过打开一个历史上被否定的单项参数可靠填平。

## 对公开排行榜差距的重新判断

现有记录中的公开项目榜分数为：Shark `12253.49`、想唉唉焦虑了 `10948.63`、DeepSpace `13463.36`，我们的旧线上确定性入口约 `10308.19`。三队公开分项的共同结构是完成天区数、请求奖励和覆盖均匀度接近，但基础分、项目加成和罚分不同。这说明它们至少提交了针对该公开项目配置的完整轨迹；它不能单独证明它们掌握了适用于未知场景的通用在线算法。

目前最合理的解释排序是：

1. 公开场景专门调参、轨迹级预计算或提交前反复试跑，概率最高；
2. 更好的局部时机/档位/覆盖联合排序，可能存在，但本轮参数筛选没有找到；
3. 评测输入或榜单聚合口径发生过变化，需要以同一提交和同一场景逐分复核；
4. 已经存在稳定、通用且完全未知的新算法，当前没有直接证据支持或排除。

因此，DeepSpace 是公开场景上的强威胁，Shark 是中等强威胁，想唉唉焦虑了超过基线但优势较小。对隐藏场景的威胁等级不能由这三个均值直接外推；要改变这一判断，需要能访问其代码/提交轨迹，或用同一批未知场景做盲测。

## 无效方向及原因

- **全知天气、事件、目标排程**：得分高但读取 reference 真值，正式入口不可用，也无法说明前向未知场景能力。
- **长时间天气持续性先验**：离线真值实验有小收益，真实预报噪声和场景分叉将收益抵消。
- **主动等待**：在时间富余的练习场景偶尔有利，但正式规模时间稀缺；等待会损失可用几何窗口。
- **提高或降低机会价格系数**：`0.9`、`1.1` 和 λ 平均方向均使完成数、覆盖或科学分回退。
- **固定长 horizon/迭代次数**：对单场有效的结果不能跨天气和请求轨迹迁移，且规划开销会上升。
- **盲目复拍和空闲填充**：旧练习场景可以利用空闲，但正式评分中请求、REQUIRED 和时间机会更重要，容易把有效曝光挤出窗口。

## 结论性更新

本轮的正式策略更新是“确认并冻结当前默认 profile”，而不是把未经大样本验证的正波动写入 `v3/agents/observer`。研究计划、当前基线和本报告均提交到 `codex` 分支；候选复制品和完整运行目录留在 `/tmp/gosim26-research-0928/` 与被忽略的 `v3/runs/`、`results/`，不进入发布包。

后续发布前只保留两项高价值核验：

1. 在真实平台代理上验证模型两个可选环节的调用成功率、超时回退和墙钟；
2. 用最终平台同一场景重放当前默认 agent，确认 fast runner 与官方 runner 的逐分一致性。

在这两项完成前，不应为了追赶公开榜单而改变默认参数或引入未来真值。
