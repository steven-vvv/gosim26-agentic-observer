## 新版引擎与策略

上游锁当前为 `9cf6f63`；变化与 PR #100 状态另见 [上游同步记录](2026-09-29-upstream-v4.md)。实际策略评测使用了引擎代码相同的 `eb1459e`；其后提交只改网站、CI 和项目准备可靠性，不改 v4 引擎或协议。限时请求引入曝光起止时间约束后，加速账本的 `record` 已传递这两个时间，避免请求进度与官方引擎分叉。`demo` 卡用加速和官方引擎复跑，四项核心产物（`decisions.csv`、`observations.csv`、`messages.jsonl`、`score_report.json`）逐字节一致。

默认策略从每轮公开快照读取 `active_requests`，过滤已完成目标，按剩余目标数分配请求奖励，要求整段曝光在截止前，并用请求门槛补充曝光时长候选。`policy.request_weight=0` 能完全关闭这一部分，便于同卡消融；周计划模型看到的也是公开请求进度，没有读取卡片真值。`demo` 同卡对照：关闭请求时 1862.83 分、请求奖励 0；开启时 1975.91 分、请求奖励 100，两边必观测遗漏均为 0。

公开 `alpha` 卡同卡消融：Claude 默认搜索参数加请求策略 24873.53 分、5/6 请求成功、必观测遗漏 1、`survey_complete`，加速评测 709.57 秒；关闭请求时 24350.90 分、0/6 请求成功、必观测遗漏 1、`survey_complete`，714.44 秒。净增 522.63 分，其中请求奖励多 500 分。它是单张公开卡的结果，不能推出隐藏卡平均收益。

大卡实测显示主要瓶颈是候选曝光时长与视场搜索的乘积。保持其余策略不变，将 `anchor_pool` 256→64、聚类锚点 8→4、关闭搜索前中心精修，并改用固定的 13 档曝光时长；精修最终候选仍开启。如下均为当前公开练习卡、无模型服务的确定性回退，限时 900 秒；`加速` 表示与官方 demo 对齐的本地替换引擎，不能等同于官方大卡运行时长。

## Agent 原生与提交物

默认配置启用模型路径；平台注入 `OPENAI_BASE_URL`、`OPENAI_API_KEY`，模型客户端发起 OpenAI 兼容的 chat 请求，每次携带符合平台代理要求的 UUID `Idempotency-Key`。周计划阶段可调整必观测奖励与门槛，行动决策阶段可在两个接近的可行观测方案中选定实际执行的动作；输出需经过候选、概率和超时校验，失败时退回确定性策略。单元测试用本地模拟 HTTP 响应走通两阶段，并验证模型选择可改变有效策略和实际动作。另用本地模型 HTTP 端点完成官方 demo 整卡：1 次 `weekly_planning`、2 次 `action_decision` 均成功，后者选中 `C1`，`survey_complete`、1904.09 分。这个模拟响应仅证明连接与执行链路，不代表真实模型质量。

主办方审查脚本会跳过 `vendor/`；新增回归测试对提交包源码运行主办方 `select_files`，确认 `README.md`、配置、`advice.py`、`policy.py`、`planning.py`、`services.py`、`llm/model_advisor.py` 均进入审查选取结果且无截断。提交时应上传独立 ZIP，不能用整个 GOSIM26 单体仓库 URL 替代：源码审查的字符上限会优先耗在 v3 等无关文件上。源码可审查和本地模拟调用不等于主办方已认定获奖资格，也不等于真实平台模型服务已完成实测。

提交前仍有外部事项：在实际参赛页面完成模型 HTTPS 端点、密钥与配额的实测，并在隐藏决赛前切为“加密保存”；公开 A–D 输入发布后检查目录、日历、光纤配置及运行预算。ZIP 哈希、体积和隔离 Python 3.12 runner 将在本记录下方归档；PR #100 和线上阶段状态仍需临提交时重新核对。

## 规模档收尾与当前结论

继续用公开 α–δ 卡做了规模对照。普通默认搜索在 α 官方引擎为 24,819.20 分、γ 为
25,428.49 分；把所有卡都压成紧凑搜索会让 α 加速结果降至 24,679.31、γ 降至
25,040.76，因此没有全局缩小搜索空间。以目标数 × 光纤数估算几何矩阵成本后，只有超过
800,000 的卡启用规模档（β：50,000 × 25；δ：30,000 × 100）：候选池 32、锚点 6、
聚类锚点 2、局部精修 1、曝光时长从 450 秒起。

规模档在加速引擎上使 β 达到 38,573.67（450 秒）和 38,701.07（600 秒），均完整结束、
必观测缺 0；δ 的 450 秒版本为 31,705.44，完整结束、缺 2，较默认加速结果低约 102 分，
但默认版本触及墙钟上限。官方 β 的 450 秒版本为 35,881.17，缺 2 并触及 900 秒；这仍比
默认官方 25,117.29 高约 10,764 分，说明官方引擎本身的计算吞吐仍是瓶颈。默认配置已把
这一档做成按公开结构自动触发的可审计配置，而不是按卡名硬编码；600 秒仅保留为实验候选，
没有在官方引擎上宣称已验收。

## Agent 原生与运行隔离修正

复核后发现，平台同时注入模型代理时，旧版 v4 诊断会把 `OPENAI_BASE_URL` 和
`OPENAI_API_KEY` 当作遥测凭据，可能让诊断事件占用模型代理配额。现已改为：专用
`TELEMETRY_URL`/`TELEMETRY_TOKEN` 才启用独立端点；只有注入 URL 的主机名与配置的遥测
主机一致时，才允许复用该代理。新增回归测试覆盖模型代理隔离和专用遥测凭据。模型仍保留
两个可审查、可回退的环节：周计划/计划自适应与行动候选选择；两者均有超时、调用预算、
候选约束和确定性回退。
