## 性能与诊断

- 原场搜索对每根光纤重复建立中心 × 时长 × 邻近目标数组。现改为按中心和光纤分组归约。四种随机数组规模（含负收益和单目标）逐元素一致；六张长卡上的动作 SHA、分数与计数完全一致，实际规划耗时约缩短 2.5 至 4.3 倍。
- `r10-policy-screen.prof` 中规划占策略耗时约 95%；此结果来自单张筛选卡，不是最终规模基准。
- 新增配对分析工具，默认拒绝缺失配对、混合源码或混合引擎；输出逐卡差值、分项收益、分位数、bootstrap 区间与完成率。显式允许不完整分析时会标注为临时结果。
- 新增固定动作重放工具，36 张 train 卡的分数、分项、计数和观测明细均与原运行一致，可还原公开质量证据。统计中的 NumPy 标量已转为原生数值，运行入口的 JSONL 行为得到单测覆盖。
- 36 张固定动作轨迹的故障诊断：当前严格规则零报告；单独放宽天气预报守门产生 15 次建议报告，其中 2 次正确、13 次误报，直接结算 -1750；单独放宽地震冷却仅 1 次正确报告，样本太少。训练集网格出现持续低质证据候选，但存在过拟合风险，尚待真实策略运行和独立数据验证。
- 高罚分训练卡的必需遗漏主要是低可见机会目标。例如 `train-r2-021` 的 270 个未达标必需目标中 252 个从未命中，未达标组的累计公开可见时间中位数约 19 小时，已达标组约 212 小时。其他高罚分卡也有类似梯度；仅靠最后可见夜排序无法表示这种稀缺机会，后续需筛选稳健的机会压力因子。
- 早期提交包两次构建 SHA-256 均为 `29d7d2cb87795a2da106a1185f4df4bf84fd708bace970d36ba52a3f3ae7ba2f`；在隔离 Python 3.12 环境中按包内清单离线安装 NumPy wheel 后，组织方本地 runner 完成 demo 卡（207 次决策、190 次观测、总分 1174.310）。冻结配置的提交包也已两次构建相同 SHA-256 `149cf90512934377667a97da6f1ca383af3104c7339c452b7f45692abb5c0a02`；再次离线安装后，组织方 runner 完成 demo 卡（359 次请求、337 次观测、总分 1664.401，正常结束、无 Agent 错误）。包内 20 个文件仅含 Agent、配置、清单、说明和两种架构的 NumPy wheel。
- 原始引擎与加速引擎的 demo、`train-r2-021` 整卡对照均保持动作 SHA、总分、分项、计数和观测账本完全一致；长卡引擎耗时分别约 11.99 与 3.48 秒，策略耗时约 41 秒，说明规划仍是主要耗时。
- 已生成 96 张独立验证卡和 64 张分布变化卡。分布变化卡第 35 张的原始种子 `1504912` 被上游生成器拒绝：多边形距极点 4.83°，低于其 5° 限制。只对该卡显式改用 `1504913`，该种子构建成功；覆盖值记录在 `v4/experiments/datasets.json`，不是根据策略结果挑选。

## 运行路径与验收

模型建议默认启用，平台提供 `OPENAI_BASE_URL` 和 `OPENAI_API_KEY` 时最多调用四次，每周规划和单步行动各最多两次；经过候选验证、置信度门槛与超时回退。每周 `balanced` 和 `coverage_focus` 的有效必需奖励/安全系数分别为 `120/0.55` 与 `200/0.52`，模型选择能改变实际规划参数；无密钥时维持冻结策略。已用本地模拟 HTTP 响应验证两种决策环节，尚无真实平台代理端点可做线上模型质量评估。

将字段中心的落山时间计算向量化后，`screen-r2-000` 的动作 SHA、评分与冻结版一致，策略耗时从 `3.484` 降到 `1.668` 秒；cProfile 显示当前单卡 `fiber_totals` 累积约 `1.19` 秒，占规划约一半，是剩余计算热点。单卡计时受并行负载影响，不能外推为大规模加速比。

最终提交包两次构建 SHA-256 均为 `81fd15c3b57e74b0fe086080d5a6f95f405154535f04e66f5edf914b29392505`，20 个文件经组织方 manifest 校验。隔离 Python 3.12.14 环境从包内 wheel 离线安装 NumPy 后，以组织方原始 `local_runner.py` 完成 `distribution-shift-r2-002`：18,000 目标、1514 次决策请求、1286 次观测动作、无 Agent 错误、`survey_complete`、总分 `3913.654893`、墙钟 `343.483` 秒，低于 900 秒上限。相同卡的新版进程内等价评测得分、分项、计数与冻结版和原始 runner 一致，动作 SHA-256 均为 `9dbab369418459f5444f4bab193e251fde7e49129b71f591ca00a0192f9c60aa`；策略计时因并行负载不同，不用作精确加速率。

验证和分布变化集均不用于追加调参；若要攻克机会选择瓶颈，应另建未见种子集评估候选策略及尾部风险。真实平台代理模型输出的效果及正式 A–D 卡表现仍未知，需要公开输入与正式运行环境才能检验。
