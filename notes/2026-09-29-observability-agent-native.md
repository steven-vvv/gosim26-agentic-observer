# 可观测性与智能体原生环节稳定性核验（2026-09-29）

## 结论

`agents/observer` 已把运行时、策略、模型请求和遥测统一到一套可观测性配置。可选模型在两个运行时环节选择：确定性策略先算候选、预期收益及启发式先验；模型若选出符合资格与概率门槛的候选，该选择会实际生效。输出不完整、格式错误、超时、超限或服务不可用时，回退确定性首选；遥测故障不改变决策。

两个模型环节是：

1. `weekly_planning`：每次引擎发布新的周预报时，在完整周方案和较短聚焦方案之间选择，并据此调整规划周期与预测范围。
2. `action_decision`：每个夜间决策至多调用一次，在确定性算法筛出的正收益候选中选择具体动作；优先级差距过大的次选直接标为不可选。

每次请求独立构造状态，包含真实游标、天气、进度、活跃请求、最近已发布的夜间窗口和周预报、评分合同、站点、日历、候选天区、确定性选项及安全门槛。候选和窗口列表有上限，优先纳入正在比较的天区，明确记录省略数量；窗口还给出全部条目的按夜/分区计数。提示中的 `prior_probability` 是启发式先验，不是经校准的胜率。上下文超过上限时不发送删掉现状的伪完整状态，直接使用确定性方案。

## 统一可观测性

- `agents/observer/observability.config.json` 统一配置本地日志、远程 Worker、事件开关、队列大小、批量大小和 checkpoint 周期。
- `Observability` 门面负责配置读取、事件开关、敏感字段清理和本地/远程分发。运行时、配置、初始化、规划、模型请求、决策追踪、协议/策略错误、checkpoint、终止和最终投递都使用同一事件模型。
- 每次实际模型请求记录阶段、选择、概率、回退原因、请求/响应字节数、首字节延迟、可见首 token 延迟、生成首 token 延迟、总耗时及上游报告的 token 用量。输出速率是全部 completion token 除以从首个生成内容到请求结束的时间，包含传输耗时，也可能包含推理 token；缺失 usage 时不估算。
- 遥测消息使用 `role=tool`、`tool_call_id/name=gosim26.telemetry` 的专用标记。同一个 OpenAI-compatible Worker 在识别标记后直接入库并返回确认，不把遥测内容转发到真实模型；普通请求才代理到上游模型。
- 终止流程先停止并排空后台队列，再单独发送最终报告；远程失败只产生服务事件和本地记录，不阻塞策略回退。

正式包使用 2048 token 生成上限、1 MiB 流响应上限、180000 字节上下文上限、18 秒调用截止时间；每阶段至多 4 次、整场至多 8 次，连续失败 3 次熔断。这些边界可在部署时通过配置或环境变量调整。

## 真实端点核验

本轮使用本机私有配置文件加载端点和密钥，没有在报告中记录密钥值或保存原始请求/响应。协议诊断发现上游合法 SSE 除简短选择文本外，还携带大量内部流式字段；合成冒烟请求的完整响应体在约 47–94 KiB。旧的 64 KiB 限制触发 `response_too_large`，512 token 上限在完整场景触发 3 次 `completion_truncated`。在提升到 256 KiB 响应上限后，合成冒烟的两个阶段均成功：

| 阶段 | 选择 | 首 token 延迟 | 总耗时 | completion token | 输出速率 | 回退 |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| `weekly_planning` | `full_horizon` | 1499.6 ms | 1559 ms | 134 | 2255.7 token/s | 否 |
| `action_decision` | `C0` | 1828.6 ms | 1852 ms | 242 | 10423.8 token/s | 否 |

两次请求均返回 `prompt_tokens`、`completion_tokens` 和 `total_tokens`，模型选择与确定性首选一致。表中的旧输出速率混用了可见首 token 延迟与包含隐藏推理 token 的 completion 用量，因此不能当作真实生成速度；现已分开计时。

在 `scenarios/comp-a-s101` 用真实 `ds/deepseek-flash` 模型和远程 Worker 的独立遥测入口完成完整 30 夜运行（1024 token / 256 KiB 响应、120000 字节上下文上限的验证中间版）：总分 182241.009106，1383 个决策、1398 个动作、1166 块完成天区，`survey_complete`，所有惩罚为 0，耗时约 221 秒。模型请求 8 次（周方案 4、行动 4），全部成功、无回退；8 个选择均与确定性首选一致。第五次周发布后已达总预算，使用确定性方案。远程遥测最终为 1753 sent / 0 failed / 0 dropped，最终报告投递成功；本地事件无序号缺口、解析错误或坏记录。最大 SSE 响应体 261486 字节，接近旧的 256 KiB 边界。

该运行还暴露两点：后续三个周方案上下文超过旧 120000 字节上限，旧逻辑只发约 1.4 KiB 的残缺状态；旧速率口径会显示不合理的极高速率。代码已修正并增加回归测试。不同运行的分数不能直接归因于模型选择，因为规划使用实时墙钟预算。

随后通过同一个 Worker 同时转发模型请求和收取遥测，以 180000 字节上下文上限、1024 token 输出上限完整复测：无残缺上下文，但 8 次请求中 2 次在输出用尽后无可见选择，触发 `completion_truncated` 并正确回退。提升到正式配置的 2048 token / 1 MiB 后再次完整复测：8 次请求全部成功、无回退，模型全部选择确定性首选；最大实际上下文 130629 字节，最大 SSE 响应 287032 字节。生成首 token 平均 1121 ms，可见首 token 平均 2968 ms，请求总耗时平均 3033 ms，平均上游报告输出速率约 216 token/s。8 次合计使用 385994 prompt tokens、3233 completion tokens；目前上游未报告可核对的缓存命中统计，不能断言固定前缀实际节省了多少计费 token。

最终复测仍为 182241.009106 分、1383 个决策、1398 个动作、1166 块完成天区，`survey_complete`、零惩罚，耗时约 199 秒。共享 Worker 的远程投递为 2094 sent / 0 failed / 0 dropped，最终报告成功；2095 条本地事件无解析错误，决策序号 1..1383 无缺口。该运行在最后一轮诊断字段整理前已启动，新增的 `policy_config` 与错误脱敏由单元测试覆盖，未在该场景运行中单独复验。

## 验证与剩余风险

自动检查覆盖 75 个 Python 单元测试、12 个 Worker 测试、ruff、TypeScript 类型检查、Worker dry-run 构建、打包配置及 `git diff --check`。带 x86_64/aarch64 NumPy wheel 的正式 ZIP 为 30.6 MiB，SHA-256 为 `d5c4ac35df746f3586d7eac23a5c6f2f9b66a216323e28ee93ba24e774282fa9`；上游项目 ZIP 校验器接受其中 14 个文件及 `jsonl-v2` manifest。正式模型和可观测性配置已通过完整真实场景验证；Worker 的流响应截止时间修复通过本地测试，部署后才会生效。上游新增的 v3 `finish` 收尾消息已由进程级回归测试覆盖，不会产生多余的协议响应；这项兼容补丁尚未做新的整场实测。

剩余风险是上游流式字段大小和延迟仍会波动，平台实际注入的超时、网络策略和两个智能体环节的资格判定也需要在提交前按真实环境确认。当前保护措施是固定前缀、每阶段/总调用上限、连续失败熔断、响应/上下文字节上限、截止时间、严格 JSON 解析、候选资格校验和确定性回退。
