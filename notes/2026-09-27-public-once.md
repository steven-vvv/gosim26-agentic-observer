# 公开场景一次性排程：结果与可复用思路

这次 ZIP 的首要目的，是在平台完整项目通道验证启动遥测。它只在初始公开信息的
`calendar` 与完整 `tile_catalog` 指纹吻合时，回放针对 `dev-reference` 或
`dev-fortnight` 预先计算的动作；其他场景走简单在线后备策略。两套日程均使用本地
场景的天气、事件和请求真值，**不能当作未知场景策略的成绩**。

| 场景 | 本地官方 runner 总分 | 已完成天区 | 请求奖励 | 空等罚分 | 对照的 CSV 最高分 |
| --- | ---: | ---: | ---: | ---: | ---: |
| dev-reference | 20788.544932 | 64/64 | 3920 | 2493.75 | 21119.494551 |
| dev-fortnight | 9872.739437 | 56/64 | 140 | 36.75 | 9882.067113 |

`dev-reference` 与对照相差 330.95 分：本方案的基础科学分和项目加成合计高约
39.40 分，请求奖励相同，但空等罚分高 370.35 分。`dev-fortnight` 相差 9.33 分；
两者均已完成该场景下可完成的请求。包内回放的 `decisions.csv` 和
`score_report.json` 在加速 runner 与官方 runner 之间逐字节相同。对照最高分来自
先前 CSV 榜单，并非这次 ZIP 已达到的成绩。

复现本次提交包：

```bash
python tools/pack_project.py --agent agents/public_once \
  --public-schedules agents/public_once/public_schedules.json \
  --telemetry-source agents/observer/telemetry.py
```

产物为 `dist/observer-public_once-project.zip`。包内无密钥；平台注入的
`OPENAI_BASE_URL` 和 `OPENAI_API_KEY` 会启用后台遥测，初始化时将同一份
`startup` 事件写入 `agent.log`。本地模拟端确认收到符合 Chat Completions
格式的请求；真实平台到 Worker 的链路仍要由这次提交确认。

可迁回通用策略的思路：

- 把“某天区的首次科学观测”和“后来满足请求的带标签重访”分开建模。reference 上
  14 个关联请求的天区提前完成首次观测，同时保留后续带请求 ID 的观测，显著减少
  空等罚分。这需要在线策略能估计请求窗口和重访机会，不能照搬具体时刻。
  reference 使用旧版计分规则：对非请求天区提前拍摄后，原计划中的无标签观测会
  被判 `duplicate_tile` 并罚分；不能把新规则的“重复观测取最高收益”套用到这里。
- 空等代价取决于当时仍未完成、可观测的天区集合。单次观测的机会价值只覆盖科学
  收益，可能错过提前完成天区带来的长期空等收益；排程目标应同时优化两者，并用
  实际 scorer 回放验证质量与等待之间的取舍。实验性联合 MILP 虽把 reference 空等
  罚分压到 247.65，却让科学收益大幅下降，总分只有 15431.52。这只是限时求解的
  可行解，不构成最优性上界。旧版 scorer 在等待开始时判断是否仍有可观测且未完成
  的天区，然后对整个等待动作计罚；保留有效的请求重访本身不会消除这项罚分。
- `tools/upper_bound.py` 的分段几何、天气及项目档位价值表适合做离线 oracle、
  回归验证和差距定位；在线只能代入预测分布，不能使用场景真值。
- 正式包可复用“指纹校验后选择场景策略、否则回退在线策略”的保护方式，以及
  单个启动事件同时写入 `agent.log` 和后台 OpenAI-compatible 遥测的做法。遥测
  不参与决策；本地模拟接收端已核对两份载荷一致，但平台代理到 Worker 的链路仍
  需要实际提交验证。

不可复用的部分：公开场景的真实天气、异常、事件、请求和精确时间表，以及
`public_schedules.json` 中的场景指纹。随机题、正式赛题或题库更新后不会命中，
不能用这次回放成绩估计未知场景的期望分数。

下一步若继续追 reference 的 330.95 分差，优先固定请求重访和 64 个首次完成，
在 150 秒网格上移动或交换首次观测，并用官方 scorer 同时衡量科学收益和精确空等
罚分。重点是少数导致长时间仍有可观测未完成天区的时段；单次局部改动没有收益只
说明邻域饱和，不证明全局最优。fortnight 仅差 9.33 分，继续投入的预期收益较小。
