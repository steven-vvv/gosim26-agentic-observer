## 主要变化

1. **v3 正常结束有明确收尾消息。** `94a6c61` 在 `survey_complete` 或 `global_wallclock_expired` 后、成绩固定之后，向 colocated Agent 发一次 `message_type=finish`，接着关闭 stdin，给最多 30 秒退出；无需回复，收尾失败不改变成绩。当前 `agents/observer` 默认在收到该消息时收尾并生成最终报告，也可通过 `termination.mode=last_slot` 保留最后响应前的兼容收尾。运行时可能在等待响应超时时已强制关闭进程，因此不能把所有时间耗尽都当作必然收到消息。对齐与验证另见 [v3 优雅退出记录](2026-09-29-v3-graceful-shutdown.md)。
2. **v4 是不同的巡天任务。** 新场景改用智利帕拉纳尔虚拟站点的光谱巡天，Agent 每次选择高度/方位指向、16 根光纤的目标分配、60–3600 秒曝光和观测程序。目标只计最好一次曝光；必观测目标的最低质量、赤经带均匀性和故障报告进入计分。Agent 仅逐步获取定性的简报、周预报和观测反馈；部分卡会发 `state_resync`。协议是 `participant-agent-protocol-v4`，仅支持 colocated，一卡至多 900 秒。v3 的天区 `observe`/`wait` 策略与响应结构无法直接使用。
3. **练习卡与正式卡准备。** 任务卡文档新增公开的 alpha（35 夜、9400 个目标）和 beta（37 夜、9500 个目标，可能 `state_resync`）；公共 `starter_kit_v4` 有 demo 卡、标准库基线、打包器和可选 LLM hook。`configure-v4-phases.py` 写明 10 月 2 日 12:00 UTC 的 go/no-go，拟将练习场切为 alpha/beta、正式场切为 A–D、隐藏决赛切为 E–H；正式场拟为每卡 900 秒、每队每天 4 批。脚本默认只预览，实际 `--apply` 前会检查活跃任务、保存快照并支持反向恢复。旧比赛规则页仍描述三个 v3 正式场景及 3600 秒，因此当前规则以线上正式公告和实际阶段配置为准。
4. **平台配套。** 新引擎按场景包识别 v4；v4 使用独立 public test 卡，平台模型适配器新增 v4 提示。分榜支持卡片标签页及总体均分，但每队各卡成绩仍来自同一个最佳完整批次，不拼接不同批次的单卡最高分。正式比赛计分前首页改显示完整项目 Playground 榜，查看成绩需核对具体阶段。练习文案进一步明确至少两个智能体技术环节的获奖要求。

## 本地核验与影响

- 用上游 `starter_kit_v4/local_runner.py` 跑 demo 基线：`survey_complete`、总分 `1232.511715`、160 次观测动作、必观测遗漏 0、无错误。demo 与 v3 场景分数没有可比性。运行输出已归档到仓库外的 GOSIM26 `/tmp` 归档。
- 重建当前 v3 ZIP 后，使用新上游 `read_project_zip` 和 `read_manifest` 验证通过：14 个文件、32,049,281 字节、`jsonl-v2` manifest。v4 manifest 字段可写 `jsonl-v4`，但平台解析时会规范为同一 JSONL 传输；这只说明包格式可接受，**不代表当前 Agent 能玩 v4**。
- 当前双环节 LLM 和共享 Worker 遥测在 v3 完成实测。v4 的 900 秒全场预算和约 5000 次决策要求重新核算每步计算成本和模型总调用预算。Worker 端点可复用，策略、状态上下文、候选生成和可靠性预算要按 v4 重做。
